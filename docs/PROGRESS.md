## Realtime / cross-panel
> **⚠️ Architecture note (2026-06-27): cross-panel pop-up alerts now ride on the
> `notifications` table, NOT on direct table subscriptions with RLS routing.**
> Hard-won lesson: Supabase Realtime `postgres_changes` can only route an event to
> a subscriber whose RLS lets them see the row — and it CANNOT reliably evaluate
> (a) a **join-based** policy (store's `order_items_manager_select`, agent's
> `try_sessions`/`order_items` rider policies) or (b) an **UPDATE that moves a row
> *into* a user's visibility** (admin assigning `deliveries.rider_id`). Both fail
> silently → "alert only goes to admin / store stopped popping". The fix everywhere:
> a DB trigger inserts a **born-visible** `notifications` row owned by the exact
> recipient, who subscribes to `notifications` INSERT filtered to their own
> `user_id` (the plain `user_id = auth.uid()` policy Realtime routes for free).
> Admin still uses `orders` INSERT directly (its policy is the simple `is_admin()`,
> which Realtime handles). Customer order-tracking uses an `id`-filtered subscription
> on its own order (born-visible). `notifications` is on the publication via 021.
